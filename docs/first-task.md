# 첫 번째 과제

> Discord 명령 기반 AI 개발팀 운영 템플릿이 실제로 한 번 끝까지 돌아가도록, 가장 작은 실전 과제를 정의한다.

## 과제 개요

첫 번째 과제는 크고 복잡한 기능이 아니라, 역할·흐름·기록이 모두 들어간 최소 운영 사이클을 검증하는 일이어야 한다.

핵심 문장:
> 첫 과제의 성공은 결과물의 크기가 아니라, 템플릿이 실제로 작동했는지에 있다.

## 과제 목표

- Discord 명령으로 작업 요청을 접수한다.
- 역할을 나누어 계획과 실행을 분리한다.
- 최소 하나의 검토 단계를 포함한다.
- 최종 결과를 문서로 남긴다.

## 권장 첫 과제: E2E 드라이런

가장 권장하는 첫 과제는 "문서 세트 + Discord 명령 흐름"을 한 번 끝까지 모의 실행하는 것이다.

### 입력

- `/request` 예시 1건
- `/plan` 예시 1건
- `/do` 예시 1건
- `/review` 예시 1건
- `/done` 예시 1건

### 실행 순서

1. 요청을 한 문장으로 요약한다.
2. 완료 기준을 적는다.
3. 역할을 배치한다.
4. 작업을 작은 단계로 나눈다.
5. 검토 후 완료 보고를 남긴다.

### 기대 산출물

- 작업 요청 요약
- 역할 배정표
- 실행 로그
- 검토 메모
- 최종 요약

## 보조 과제: 문서 세트 완성

이 템플릿의 기본 산출물은 아래 5개 문서다.

- `README.md`
- `docs/agent-roles.md`
- `docs/workflow.md`
- `docs/project-roadmap.md`
- `docs/first-task.md`

이 과제는 템플릿의 설명서를 정리하는 데 유용하지만, 단독으로는 실제 운영 흐름 검증이 약할 수 있다.

핵심 문장:
> 문서 세트는 단순한 설명서가 아니라, 이후 모든 작업의 운영 규칙이다.

## 완료 기준

다음 조건을 모두 만족하면 첫 과제가 완료된 것으로 본다.

- 요청이 명확하게 기록되었다.
- 역할 분담이 이루어졌다.
- 작업이 최소 한 번 실행되었다.
- 검토 결과가 남았다.
- 최종 상태가 문서에 정리되었다.

핵심 문장:
> 완료 기준이 없으면 첫 과제는 끝나지 않고, 그냥 잠시 멈춘 것처럼 보일 뿐이다.

## 실패 시 확인할 항목

- 요청이 너무 컸는가
- 역할이 겹쳤는가
- 검토 기준이 불명확했는가
- 종료 보고가 부족했는가
- 다음 작업으로 넘길 기록이 없었는가

핵심 문장:
> 실패 분석은 부가 작업이 아니라, 다음 실행의 품질을 올리는 핵심 단계다.

## 첫 과제용 템플릿 문장

- "이 과제의 목적은 템플릿이 실제로 작동하는지 확인하는 것이다."
- "완료 조건은 산출물과 검토 기록이 모두 남는 것이다."
- "이 작업은 한 번 성공하는 것이 아니라, 다시 실행할 수 있어야 끝난다."
