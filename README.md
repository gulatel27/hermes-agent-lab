# Hermes Agent Lab

> Discord 명령으로 AI 개발팀을 운영하는 실무형 템플릿.

Hermes Agent Lab은 Discord를 운영 인터페이스로 사용해, 요청 접수 → 역할 배정 → 실행 → 검토 → 기록까지 이어지는 협업 표준을 문서로 고정하는 프로젝트다.

## 왜 필요한가

- 누가 무엇을 맡는지 매번 다시 설명해야 하는 문제를 줄인다.
- 작업 요청을 바로 실행 가능한 형식으로 표준화한다.
- 중간 검토와 최종 승인 기준을 명확히 한다.
- Discord 대화가 작업 기록으로 남도록 만든다.

## 이 저장소의 범위

이 저장소는 코드 데모보다 운영 템플릿에 초점을 둔다.
핵심 산출물은 아래 문서다.

- `docs/agent-roles.md` — 역할 정의와 책임 경계
- `docs/workflow.md` — Discord 명령부터 완료 보고까지의 흐름
- `docs/project-roadmap.md` — 단계별 구축 순서와 종료 기준
- `docs/first-task.md` — 첫 번째 실행 과제와 성공 조건

## 핵심 원칙

1. 명령은 짧게, 기준은 문서로 고정한다.
2. 역할은 고정하되, 책임 경계는 겹치지 않게 한다.
3. 작업은 작게 나누고, 각 단계의 완료 조건을 적는다.
4. 결과는 다음 작업의 입력이 될 수 있어야 한다.
5. 실패해도 복구 가능한 운영 구조를 먼저 만든다.

## 추천 최소 운영 구조

초기에는 다음 4개 역할만으로 시작하는 것을 권장한다.

- Orchestrator: 전체 우선순위와 분배 조정
- Builder: 실제 산출물 작성
- Reviewer: 요구사항 충족 여부 검토
- Recorder: 의사결정과 결과 기록

나머지 역할(QA, Ops, Planner)은 프로젝트가 안정화되면 확장한다.

## 운영 방식

### 사용자 상호작용

- 사용자는 Discord에서 짧은 명령으로 요청한다.
- 에이전트는 요청을 작업 단위로 분해한다.
- 산출물은 문서, 체크리스트, 실행 로그 형태로 남긴다.

### 작업 흐름

1. 요청 접수
2. 계획 수립
3. 실행
4. 검토
5. 종료 보고

### 완료 기준

다음 조건을 만족해야 작업이 끝난 것으로 본다.

- 요청과 결과가 일치한다.
- 검토가 완료됐다.
- 결정 사항이 기록됐다.
- 다음 사람이 이어서 볼 수 있다.

## 첫 번째 목표

이 프로젝트의 1차 목표는 “Discord 명령 기반 AI 개발팀 운영 템플릿”을 저장소에 구축하는 것이다.

즉, 에이전트를 더 똑똑해 보이게 만드는 것이 아니라, 팀처럼 일하게 만드는 것이다.

## 다음 단계

1. 문서 세트를 확정한다.
2. Discord 명령 포맷을 고정한다.
3. 첫 작업을 한 번 끝까지 실행해 본다.
4. 실패 지점을 기록하고 템플릿을 개선한다.
